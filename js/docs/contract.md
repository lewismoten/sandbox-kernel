# Sandbox JS contract inventory (slice 0)

What the kernel offers a JavaScript runtime, and what the runtime will offer a JavaScript OS in return. Snapshot: kernel branch `feature/rpi-keyboard-1113` at `e67d02f`, **ABI 1.12** (`include/abi.h`, `core/sys.c`, `sdk/include/sandbox/abi.h`), 2026-11-13. The machine-readable copy is [`../contract.json`](../contract.json); `python3 js/tools/contract.py check` validates it and fails if the kernel gains a syscall number or `SBX_IOC_*` request that has no entry. The tables below are generated by `contract.py md`; edit the JSON, not the tables.

## Defaults (Lewis can change any of these)

| Question | Default used here |
| --- | --- |
| Name | **Sandbox JS** |
| Trust | v1 runs trusted maker apps. There is no promise to isolate hostile code from the rest of the JS OS or from the card; only the kernel's own fences (MMU user mode, handle and path rules, heartbeat) hold. |
| Home | `js/` inside sandbox-kernel, on feature branches. No new GitHub repository (making a public one is Lewis's call). |
| UI | A DOM-lite UI profile ships in v1. The Game-Maker profile (the `game` element and play core) stays owned by gamemaker-os. |
| Launcher | The recovery picker is always embedded, so a broken app never leaves a card without a way back. |
| Size | The 1 MiB ELF/install ceiling is firm for v1. Growth trims profiles first. |

## How to read the tables

- **Kernel**: name and number as the kernel has them (ioctl = class<<16 | op, written in hex).
- **JS API**: the proposed shape. Names are provisional until slice 1; the shape (sync or not, what is thrown, what is returned) is the contract.
- **Sync**: the kernel has no blocking calls except card access and `sleep_until`, so every kernel call is synchronous from the core's point of view. The JS layer is asynchronous only where a promise or event is the natural JS shape (timers, input events, audio refill); each such place says so.
- **Errors**: the kernel returns 0 or a negative errno. The JS wrapper throws `SandboxError {code, errno, call, abi}`, with two exceptions: `EAGAIN` is not an error (reads return nothing, audio returns a short count), and `ENODEV` on an optional device means "feature absent" (`eink.available === false`).
- **Capability**: what a manifest must grant. Slice 3 turns these into the manifest validator and the checks (see [apps.md](apps.md)). Names: `fs.read`, `fs.read.shared` (added in slice 3: card reads outside `/sd/OS`), `fs.write.cache`, `fs.write.saves`, `display`, `input`, `audio`, `eink`, `serial`, `power`, `time`, `log`, `app.lifecycle`, `memory`.
- **Status**: `v1` (in the first release), `later` (useful, not needed yet), `not-exposed` (the core uses it, or it is reserved; the reason is in the cell).
- **Test plan**: the host-model case that proves the binding. The kernel's host tests (`make test`) already cover the kernel side; these lines are the JS side.

## Rules every binding follows

1. Check `startup.minor` before using a call newer than 1.0, and map an old kernel's `ENOSYS`/`ENOTTY` to a clear "needs ABI 1.N" message (`sys.has(feature)`).
2. Zero every output field and unknown tail before a call; records are 8-byte aligned, little-endian (`docs/os-authors.md` section 3).
3. Handles are generation-tagged. A closed handle's JS object throws `EBADF` on reuse and never silently reaches another handle that took the slot.
4. At most 16 kernel handles at once. The runtime budgets them (slice 3) so an app cannot starve the picker.
5. A failed call does not promise that buffers or device state are untouched, so wrappers do not hand partial results to the app after a throw.
6. The heartbeat (call 17) belongs to the core. Nothing an app does may delay it past the kernel's deadline.

### Gaps

| ID | Title | Problem | Owner | Proposal | Priority |
| --- | --- | --- | --- | --- | --- |
| G1 | Input wait | No blocking read or poll: input must be opened nonblocking and sleep_until does not wake on input. JS must poll between sleeps, costing latency or power. | kernel | A wake-on-input flag for sleep_until, or a blocking input read that still serves the heartbeat | high |
| G2 | Writing files | Only whole-file WRONLY\|CREAT\|TRUNC to 8.3 names under CACHE or SAVES/GAME; no append, read-write, mkdir, unlink, stat, or writes elsewhere; 1 MiB per file held in kernel RAM; one writer. JS fs.writeFile and an OS that keeps its own data cannot be built on it. | kernel | unlink, mkdir, a per-OS data folder (for example /sd/OS/DATA/<OS>/), long names, append | high |
| G3 | Heartbeat during sleeps | sleep_until does not extend the heartbeat deadline and the allowed interval is not in the ABI. A long timer wait must be chopped into slices by the runtime. | docs + kernel | Publish the heartbeat limit in the startup record; let sleep_until count as progress up to it | medium |
| G4 | Memory | No anonymous mmap, free or resize; one 2,195,456-byte arena per run plus the ELF's own image (1 MiB ceiling). Typed arrays for images and sound compete for it. | kernel | A second arena or a resizable one (separately authorized) | medium |
| G5 | Process model | No exec or launch-next: switching apps means exiting back to the kernel or launcher, and the kernel passes no argv or app name. Today the convention is /OS/AUTORUN.TXT: the kernel reads line 1 (the ELF), JS.ELF reads line 2 (the app). That works for a boot-time app but not for one app starting another with an argument. | kernel/launcher | Keep the AUTORUN.TXT line-2 convention for v1; ask for a launch request with a short argument string only if app-to-app launch is needed | medium |
| G6 | Text input | The input queue carries key codes, no characters, layouts or composition. KeyboardEvent.key and typed text need a JS keymap that assumes a US layout. | JS + kernel | Report the HID usage and modifier state, or the layout, to the OS | low |
| G7 | Entropy and wall time | No random source and no real-time clock. Math.random needs a seed from boot jitter; Date is meaningless. | kernel | getrandom-style call; optionally a time source or a way for the host to set it over USB | medium |
| G8 | Audio feedback | Write is nonblocking with a 341 ms ring and no wake on drain, and the rate is fixed at 48 kHz. A JS player must poll audio.stats() and schedule itself. | kernel | A blocking write or a readiness signal | low |
| G9 | Display sync | FB_PRESENT is a synchronous copy; there is no vsync wait, page flip, or display-size query beyond the negotiated mode, so tearing and frame pacing are on the runtime. | kernel | Present-complete or vblank timestamp | low |
| G10 | Execution control | No timer signal or preemption: a runaway script is stopped only by the interpreter's own interrupt hook in userland and the heartbeat watchdog in the kernel. | JS (slice 5) | None needed; documented as the isolation limit of v1 | medium |

## Counts

49 entries: 25 syscall rows (19 implemented call numbers, several split by operation or path, plus 5 reserved numbers), 11 ioctl requests, 2 device/event rows and 2 record rows. By status: 40 `v1`, 2 `later`, 7 `not-exposed` (the 5 reserved numbers, `health`, `app_arena`).

## Not in the kernel at ABI 1.12 (so not in the contract)

Gamepads, Wi-Fi, Bluetooth, anonymous `mmap`, general SD writing, and the planned `/state` journal store (`docs/os-authors.md` section 4). HDMI audio output, e-ink on hardware and the serial link are hardware-untested; a JS binding for them is verified against host models only until Zero W qualification (design question 8: who owns it).
